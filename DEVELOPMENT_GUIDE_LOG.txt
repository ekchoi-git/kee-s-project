[USER]
이제 내가 이 프로젝트 완성을 위해서 뭘 해야할지 상세하게 알려줘.

[ASSISTANT]
현재는 **PRD v0.3과 대화 로그를 정리하고 GitHub에 저장한 상태이며, 프로그램 코드는 아직 없습니다.** 이제 문서를 더 늘리기보다, 실제 Excel 연결과 되돌리기가 가능한지 확인하면서 개발을 시작할 단계입니다.

직접 맡으실 일은 **사용 환경 준비, API 연결 정보 준비, 업무 결과 판단, 사용성 피드백**입니다. 코드 작성과 테스트 데이터 생성, 기능 구현, 커밋·푸시는 제가 맡으면 됩니다.

**1. 먼저 개발·시연할 PC를 정해주세요**

가장 먼저 정할 것은 “어느 PC에서 실제 Excel을 조작할 것인가”입니다.

- 현재 이 프로젝트를 작업하는 PC에서 Excel을 실행할 수 있는지
- 그 PC에 Microsoft 365 데스크톱 Excel이 설치되어 있는지
- 최종 시연도 같은 PC에서 할 것인지
- 개발에 필요한 프로그램을 설치할 수 있는지

이 조건을 확인하면 됩니다. Excel의 자세한 버전·비트수와 개발 도구 설치 상태는 개발 시작 시 제가 확인할 수 있습니다. 무엇을 설치해야 할지 지금부터 직접 찾아보실 필요는 없습니다.

가능하면 개발과 시연을 같은 PC에서 진행하는 편이 환경 차이를 줄이기 좋습니다.

**2. 가지고 있는 API의 연결 정보를 준비해주세요**

새 서비스를 구매하기 전에, 이미 가지고 있는 키 중 하나로 실제 연결이 되는지부터 확인하면 됩니다.

준비할 정보는 다음과 같습니다.

- 어느 공급자의 API인지
- API 사용 안내문 또는 호출 예제
- 호출할 모델 이름
- 별도로 지정해야 하는 접속 주소가 있는지
- 사용량 제한이나 비용 한도를 확인할 수 있는지

기술적인 내용이 이해되지 않아도 괜찮습니다. **키를 가린 안내문이나 호출 예제**를 보여주시면 제가 필요한 설정을 구분하겠습니다. 키 자체는 채팅이나 GitHub에 올리지 않고, 개발 단계에서 안내하는 로컬 설정에 넣으면 됩니다.

이 단계의 완료 기준은 키를 보유했다는 사실이 아니라, **시연 PC에서 한국어 요청을 보내고 실제 응답을 받는 것**입니다.

**3. 실제로 시연하고 싶은 명령과 기대 결과를 정해주세요**

이 부분이 사용자에게 가장 중요한 역할입니다. “어떤 결과가 업무적으로 맞는가”는 제가 임의로 정하기 어렵기 때문입니다.

우선 아래 정도의 명령으로 시작하면 충분합니다.

| 시연 명령 예시 | 확인할 결과 |
|---|---|
| “회사별·연도별 합계를 수식으로 만들어줘” | 실제 수식과 올바른 합계 |
| “같은 내용을 피벗 테이블로 만들어줘” | Excel에서 수정·새로고침 가능한 피벗 |
| “금액이 일정 기준 이상인 거래만 보여주고 내림차순 정렬해줘” | 조건에 맞는 행과 올바른 정렬 |
| “거래 설명을 보고 유형을 구분해줘” | 업무상 납득할 수 있는 분류와 기준 |
| “중복·누락·이상 의심 항목을 표시해줘” | 정상 데이터와 의심 항목의 구분 |
| “표시한 항목 중 이 조건에 해당하는 것만 수정해줘” | 지시한 대상만 수정 |
| “여기서 회사별 건수도 추가해줘” | 앞선 맥락을 이해하는 후속 작업 |
| “방금 작업 되돌려줘” | 직전 상태 복원 |

완벽한 정답표를 직접 만들 필요는 없습니다. 예를 들어 다음처럼 알려주시면 됩니다.

> “이 설명은 인프라 사용료로 분류되면 맞고, 인력 용역으로 나오면 틀린 거야.”

이미 보내주신 합성 데이터가 있으므로 **테스트 자료를 처음부터 다시 만들 필요도 없습니다.** 이를 실제 `.xlsx` 파일로 만들고, 중복·누락·애매한 설명과 1만 행 데이터를 추가하는 작업은 제가 맡을 수 있습니다.

**4. 개발은 다음 순서로 진행하겠습니다**

약 2주는 개발 착수일부터 10개 작업일을 기준으로 잡겠습니다.

| 기간 | 제가 진행할 작업 | 직접 확인하실 내용 |
|---|---|---|
| 1~2일차 | Excel 연결, 셀 읽기·수식 입력, 실제 피벗 생성, API 연결, 복구 방식 검증 | 시연 PC에서 실행 가능한지, 기본 결과가 맞는지 |
| 3~4일차 | 대화창, 자연어 해석, 즉시 실행, 범용 수식과 집계 기능 | 원하는 말투의 명령이 통하는지 |
| 5일차 | 필터·정렬, 후속 요청, 관련 되돌리기 | 실제 업무 순서대로 이어서 사용할 수 있는지 |
| 6~7일차 | 의미 분류, 데이터 검증, 지시한 항목 일괄 수정 | 분류와 의심 항목 판단이 납득되는지 |
| 8일차 | 대표 함수·배열 수식, 1만 행 처리, 실패·충돌·복구 검증 | 처리시간과 결과 안내가 사용하기 적절한지 |
| 9~10일차 | 실행 파일 제작, 시연 PC 테스트, 결함 수정, 사용 안내 | 개발 명령어 없이 실행하고 전체 시연이 가능한지 |

**첫 1~2일의 핵심은 실제 Excel 조작과 복구 검증입니다.** 이 결과를 확인한 뒤 화면과 기능을 확장해야 일정 판단이 정확해집니다.

**5. 개발 중에는 짧고 구체적인 피드백을 주시면 됩니다**

중간 결과가 나오면 실행해보고 아래 세 가지만 알려주세요.

- 무엇을 시켰는지
- 실제로 어떻게 됐는지
- 어떻게 됐으면 좋겠는지

예를 들면:

> “회사별 합계를 요청했는데 공급사번호별로 나뉘었어. 회사명이 같으면 합쳐졌으면 좋겠어.”

오류가 나면 화면의 오류 문구와 직전에 입력한 명령을 함께 알려주세요. 기술적인 원인을 직접 분석하실 필요는 없습니다.

가능하면 하루에 한 번 정도 짧게 확인하고, 수정 요청은 반드시 고칠 문제와 나중에 추가할 기능으로 구분하면 좋겠습니다. 새 기능이 생기면 PRD와 2주 일정에 미치는 영향은 제가 설명하겠습니다.

**6. 마지막에는 아래 기준으로 완료 여부를 함께 판단하면 됩니다**

- 실행 파일을 열면 실제 Excel에 연결된다.
- 자연어로 지시하면 사전 승인 없이 작업이 실행된다.
- 실제 수식·피벗·필터·정렬이 적용된다.
- 분류 기준과 의심 항목의 이유를 확인할 수 있다.
- 후속 요청이 앞선 작업 맥락을 이어받는다.
- 직전 AI 작업을 되돌리면 관련 값·수식·서식·순서 등이 복원된다.
- 오류나 일부 실패를 성공으로 표시하지 않는다.
- 1만 행에서 측정한 처리시간과 지원 한계가 정리되어 있다.
- 같은 과정을 최종 시연 PC에서 다시 실행할 수 있다.

지금 바로 준비하실 것은 **개발·시연 PC 확인, 키를 가린 API 안내 자료, 우선 시연할 명령 몇 개**입니다. 다음 개발 작업은 그 환경에서 **Excel 연결 → 수식·피벗 적용 → 되돌리기 → API 연결**을 실제로 검증하는 것입니다.
